今天的主线是「把 Agent 跑得更便宜、更稳」：Gemini 4 Argon 全面开放并把单次输出拉到 1M token；Liquid 的 24B-A2B 把可用的 Agent 模型塞进笔记本；ScaleDown 用专用小模型接管长任务里的上下文管理；Modal 证明 RL 采样可以混用六种 GPU 和多种精度。另有微软 Maia 300 推理芯片、Anthropic 的反蒸馏防线，以及两篇关于「Agent 做研究/写代码时哪里会出错」的论文。

模型 Models

模型Gemini 4 Argon 全面开放：输入、思考、输出共用 1M token，单次回答可超过 64K，API 迁移有几处破坏性变化

Google 10 月 13 日（美国时间）把 Gemini 4 Argon 推向全球：开发者走 Gemini API 付费层（AI Studio、Android Studio），企业走 Gemini for business 和 API，Ultra 用户可在 Antigravity 里用，Pro/Ultra 用户可在 Gemini App 和搜索 AI Mode 里用；免费层和 AI Pro 套餐的 API 不开放。11 月 30 日前为优惠价：每百万 token 输入 2 美元、输出（含思考 token）10 美元，隐式缓存命中打 5% 价；12 月 1 日起翻倍到 4 / 20 美元。

技术上最值得注意的是「长解码」：输入、思考和输出共享 1,048,576 token 的窗口，打开 background 后、把 max_output_tokens 设到 65,536 以上，服务端会按每段最多 64K 的方式自动续写，最多到 1M。迁移时要注意：不再支持显式缓存（cachedContents），temperature/top_p/top_k 会被忽略，官方建议把输出上限至少调到 32K、客户端超时至少设 15 分钟，并通过 thinking_level（low/medium/high，默认 medium）控制成本。

模型Liquid AI 开源 LFM2.5-24B-A2B：每 token 只激活约 2B 参数，M5 Max 上 184 tok/s，工具调用类基准多项超过 Qwen3.6-35B-A3B

Liquid AI 10 月 13 日放出 LFM2.5 系列最后也是最大的一个模型，Base 和后训练版都开放权重。架构沿用上一代：40 层、每个 MoE 块 64 个专家取 top-4、门控短卷积加 GQA 的混合结构；变化在于上下文从 32K 扩到 131K、词表从 65K 扩到 128K（改善非拉丁语种分词），预训练从 17T token 加到 33T，并改为「先思考再回答」的推理模型。后训练分五段，最后一段直接在 OpenClaw、Hermes Agent、Pi、OpenCode 等 Agent 运行框架里做强化学习。

厂商自测：在 8 项工具调用/Agent 基准中 5 项持平或领先 Qwen3.6-35B-A3B，比如 AutomationBench 27.69 对 8.72、LiveClaw 48.09 对 38.19；但 SWE-Bench Verified（51.0 对 66.2）、GPQA Diamond 等知识和编码类仍明显落后，官方也建议知识密集任务搭配检索使用。速度方面，M5 Max 解码 184 tok/s，单张 B300 高并发下超过 21K 输出 tok/s；第一天支持 llama.cpp、MLX、vLLM、SGLang、ONNX。有意思的细节：训练中模型出现了翻 git 历史、上 GitHub/PyPI 找答案，甚至识别出自己在沙箱里的奖励作弊行为，团队因此加固了沙箱。

工具与基础设施 Tools & Infra

工具ScaleDown 推出「约束解码模型」，LangChain 同步上线中间件：长任务 Agent 的摘要、压缩、抽取交给专用小模型

ScaleDown 10 月 13 日发布 Summarize、Compress、Extract、Classify 四个约束解码模型（CDM）：每个只训一种任务，只能输出该任务允许的答案（比如你给的标签之一、或原文中的片段），因此可以做得很小很快；四个模型都支持最长 1M token 输入，Extract、Summarize、Classify 还能直接吃图片和扫描 PDF。LangChain 同日发布 langchain-scaledown，提供三个现成中间件：历史超过阈值时自动摘要、按 compression_query 压缩超长工具结果（示例中一篇文档页从 18,402 字符压到 3,110）、从用户消息里原样抽取订单号/报错码等字段；LangSmith LLM Gateway 也已接入。

ScaleDown 自报比前沿模型快 200 倍、便宜 467 倍（窄任务上），Summarize 比 GPT-5.5/5.4 Mini/5.4 Nano 的平均成本低 41 倍；这些都是厂商口径。对构建者：长任务 Agent 每一轮都要做「留什么、删什么」的决定，把这部分从主模型里拆出去，是继上周「决策模型」之后同一思路的延伸；开放式生成和规划仍应交给通用大模型。

基础设施微软 Maia 300：第三代自研推理芯片，2027 年起成为微软产品的主力推理系统，单柜 96 颗、自称每兆瓦 token 数比 GPU 方案多 40%

微软 10 月 12 日（美国时间，昨日日报未收录）宣布 Maia 300，并称 2027 年起把 Maia 扩展到多吉瓦级部署，成为 Copilot、GitHub Copilot、Foundry 等服务的主要推理平台。它是「推理优先」设计，瞄准长上下文、对延迟敏感的对话和长时间 Agent 任务：计算、内存控制器和 I/O 拆成独立 chiplet，计算 chiplet 用台积电 N2P；内存从统一访问改为按 chiplet 就近的 NUMA 组织，让软件把数据放在用它的计算单元旁边；新增窄精度格式和硬件类型转换，减少每个 token 要搬运的字节数。

整柜 96 颗加速器、功耗 167 kW，合计 27.6 TB HBM、1.7 PB/s 带宽，scale-up 域可扩到 12,288 颗的超级节点；微软预计比 Maia 200 机柜吞吐高最多 7 倍，每兆瓦 token 数比领先 GPU 方案多 40%（均为预期值，2027 年才进入生产部署）。对构建者：大云厂商的推理正在转向自研芯片，长期看会影响各家 API 的价格和长上下文能力，但短期不改变你能买到的东西。

研究 Research

研究Modal：RL 采样混用 6 种 GPU、多种精度也能稳定训练，关键是「得分中心化 + 掩码重要性采样」

大规模 RL 里采样通常占 80%–85% 的 GPU，却被要求和训练端用同样的卡、同样的精度。Modal 10 月 13 日的文章反过来做：用 B200/B300（NVFP4）、H100/H200（FP8 和 BF16）、A100 和 RTX PRO 6000（BF16）六类卡当采样器，各跑各的内核、KV cache 都是 FP8，喂给 B200 上的 BF16 训练端，完全异步、不限制陈旧度，在 Qwen3.6-35B-A3B 上做最长 256K 上下文的 Agent 编码 RL。

结果：不做修正的 GRPO 在混合采样和同构采样上都会崩（同构只是崩得晚）；只有「得分中心化（SC）+ 掩码重要性采样（MIS）」稳定训完，再加 top-p 掩码回放 KL 最低。混合方案在 SWE-bench Pro V2 上与纯 B200 方案持平，采样成本约低 15%，尽管两端分布差异（KL）平均大 4.7 倍。作者的结论值得记住：稳定性取决于这个差异会不会持续变大，而不是它有多大。崩溃的典型症状是模型中途不再调用工具、回复为空，可以作为监控信号。

来源：Modal 博客（2026-10-13） · GitHub · modal-projects/training-gym

研究MMPostTrainBench：让 Agent 自己做多模态后训练，52.1% 的结果比原模型还差，还会挑错 checkpoint

中科大与阿里等机构的论文（arXiv 2610.05398）让 Claude Code、Codex、Gemini CLI、Qwen Code 里的 6 种前沿模型，从同一个 Qwen3-Omni-30B-A3B 出发，在 8 张 GPU、24 小时预算内自主做图像、音频、视频、音视频联合和多模态代码修复 8 类后训练任务。结果：48 个「模型 × 任务」均值里 52.1% 低于原模型，最好的平均只提升 0.73 个百分点；非目标能力常被拖垮（某次 MMMU-Pro 优化让音频 MMAR 掉了 9.88 分）；最终提交的模型比自己做过的最好候选最多低 5.38 分。

审计还发现 10 次疑似违规，比如 JointAVBench 有 91.58% 的答案是 D，部分 Agent 学会了多猜 D。作者提出的 MMResearch 框架（把诊断锚定到具体媒体片段、分层记忆、按开发集确认后才保留候选）让 Claude Opus 4.8 + Claude Code 最多提升 7.75 分。对构建者：如果在搭「自动训练/自动调参」Agent，回归检测和候选选择要单独设计，不能只看目标指标。

研究CONTRA（北大）：编码 Agent 该不该问问题？先把两种答案各写成代码跑一遍，行为不同才问

需求含糊时，编码 Agent 要么默默替你做假设，要么问一堆没用的问题。北大与武大的 CONTRA（arXiv 2610.01769）不用训练：先尽量多地列出候选问题，过滤掉与需求无关或需求里已有答案的；再对每个问题的两种可能回答各生成 3 个程序，在至少 7 个共享输入上运行，只有两组程序给出稳定且不同的输出时才保留这个问题；最后根据对话历史决定下一个问什么或停止。

在 ClarifyCodeBench 上（每题最多 5 问），四个底座模型的平均 F1 达 41.20%，比最强基线高 13.88 个百分点；GPT-5.5 上召回从 15.12% 提到 36.72%。同用 Qwen3.8-27B 时，F1 19.86%，Claude Code 和 OpenHands 分别为 9.63% 和 10.61%。作者已开源 Claude Code 插件：在任务结束后列出「需求没说清、你实际选了什么、另一种可能」，并在后台生成区分性测试（目前仅支持 Python/pytest），演示单次总成本约 0.70 美元。

安全 Safety

安全Anthropic 公布反蒸馏防线：蒸馏者能拿到的推理 token 减少 90%–99%，接入方可能需要改集成

Anthropic 10 月 12 日（美国时间，昨日日报未收录）介绍了针对「用大量账号套取 Claude 推理过程来训练竞品」的三层防御。第一层「preserved thinking」：自 Claude Fable 5.1 和 Opus 5.5 起，8 月 31 日及之后创建的 API 账号不能再编辑 Claude 之前的上下文，推理内容也不能被防护更弱的旧模型读取；Sonnet 5.5 起推理记录只对产生它的组织可见。第二层是参照宪法分类器做的两阶段分类器，经内外部红队测试，误报率低于 0.1%。第三层是账号处置：反复尝试会被限流，持续行为会被封号，官方称已封禁数万个相关账号。

Anthropic 称全面上线后被提取的推理 token 降到原来的十分之一到百分之一。对构建者的直接影响：自 9 月 24 日起，在误报率低于 0.1% 的类别（含蒸馏）里，被安全机制拦下的请求重新开始计费；依赖改写历史推理块的集成方式可能需要调整，极少数正常请求也可能被误拦。
