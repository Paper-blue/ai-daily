过去约 24 小时的主线是「高危能力怎么放、Agent 怎么进门和担责」：Mistral 发布 1T 参数的 Mistral Large 4 预览、主打不拒答的网络安全能力，Anthropic 则把 cyber 能力改成三级审核放行；Meta 与 Sierra 牵头提出 Personal Agent Protocol，美国两党参议员提案让 Agent 开发者和运营者为黑客行为担责。另外，OpenAI 一次性公开 722 篇由内部模型产出的数学手稿，Google 发布 740M 参数的多模态嵌入模型 EmbeddingGemma 2。

模型 Models

模型Mistral Large 4 公开预览：1T 总参 / 49B 激活的原生多模态模型，权重计划月底开放

Mistral 10 月 6 日上线 Mistral Large 4（ML4，昵称 “le Chonk”）的预览 API：总参数 1 万亿、激活 49B，原生多模态。官方称它在自家欧洲数据中心用 3,800 张 NVIDIA Grace Blackwell GPU 从头训练，权重会在月底开放；在此之前，网络安全机构、审核过的合作方和政府部门会拿到审核更宽松、cyber 能力更强的同一模型做实战红队测试。

官方自报成绩：DeepSWE v1.1 61.7%、Terminal-Bench 4 28.3%、Cybench 93%，Lakera B3 提示注入攻击抵御率 93.3%。官方还特意指出，Claude Opus 5.5、GPT-6 Astra 等闭源模型在某项「复现并修补真实漏洞」的测试里因为拒答几乎得零分。RL 部分透露：约 3k GPU 规模下，单次训练每天产出约 330 亿 token，过滤后约 160 亿可训练。对构建者：这是欧美阵营少有的万亿级开放权重候选，适合需要私有化部署、不想被供应商拒答卡住的安全团队；不过架构细节和更多基准还没公布，权重放出后再实测。

来源：Mistral · Introducing Mistral Large 4（2026-10-06） · TechCrunch

模型Google EmbeddingGemma 2：740M 端侧多模态嵌入模型，文本/代码/图像/视频/音频进同一向量空间

Google DeepMind 10 月 6 日发布 EmbeddingGemma 2，基于 Gemma 4 架构，Apache-2.0 许可。它把文本、代码、图像、视频和音频映射到同一个 768 维空间，并且是模块化的：纯文本只要 270M 参数，视觉（170M）和音频（300M）编码器按需加载；支持 Matryoshka（MRL）截断到 512/256/128 维，向量存储最多省 6 倍。上下文 8K（一代的 4 倍），可一次处理约 5.5 分钟音频、29 张图或 58 帧视频。

官方数据：MTEB Code 从 68.76 提到 78.68；量化后在 Pixel 11 Pro 上纯文本约需 191MB 活跃内存，完整多模态约 567MB。它和 Gemma 4 共用文本 tokenizer 与音频编码器，两者一起跑能省内存。对构建者：做本地 RAG、相册/视频检索或代码库索引，可以用一个小模型替换「文本嵌入 + CLIP + 音频嵌入」三套模型；transformers、sentence-transformers、llama.cpp、vLLM、Ollama 等已支持。

来源：Google Blog · EmbeddingGemma 2（2026-10-06） · The Verge

研究 Research

研究OpenAI 在 GitHub 公开 722 篇 AI 数学手稿（372 个结果族），但没公开提示词和模型

OpenAI 于美东 10 月 6 日 18:00（北京时间 10 月 7 日 06:00）在 openai/math 仓库公开一批由未发布内部前沿模型产出的数学成果：722 篇手稿，归为 372 个相关结果族，附证明材料、部分结果的 Lean 形式化证明和 10 份删节版推理摘要。官方称这批结果来自约 4,000 道题的评测，平均每个结果的算力大约相当于 ChatGPT Pro 思考 3 小时；仓库还定了论文修订和引用规则，旧版本会一直保留。

据 Scientific American，结果里包括四维 Kakeya 猜想的解答，以及在黎曼猜想方向上的进展；OpenAI 发言人称几乎所有结果都由单个 Agent 在单次提示下完成（也承认部分结果试了多次）。争议在于：独立顾问组 AGMAI 建议公开模型、精确提示词和每个结果的算力，但 OpenAI 只给了平均算力，没有提示词，模型也没开放，MIT 数学家 Andrew Sutherland 说「要看收据」。对构建者：Lean 可验证的部分基本可信，但「单 Agent 一次搞定」这类说法在模型和提示词公开前，无法复现。

来源：OpenAI Developer Community 公告 · GitHub · openai/math · The Verge · Scientific American

研究VERA：把基准轨迹变成 9,000+ 个可验证训练环境，让模型权重和 Agent harness 交替进化

NVIDIA 与 UCSC、清华等的论文 arXiv:2610.05923（10 月 5 日提交）提出 VERA。第一步用 Auto-Rubric 把基准轨迹切成计划、准备、验证、执行、提交五个阶段，每个阶段都能从中间恢复的沙盒，由编码 Agent 写二元评分细则和可执行检查，Agent Judge 进工作区核验，可执行检查不过就直接判零。第二步交替更新：冻结 harness，用细则奖励跑全参数 GRPO；冻结模型，增删合并 skill，每次改动都要在开发集上做配对对比，确认有提升才保留。

结果：9B 模型比最强的单维度基线在 CoWork 和医疗研究两个领域分别高 10.3 和 13.0 分；27B 在 AutoCoWorkBench 得 71.6、AutoMedBench 得 80.7。代价也写得很清楚：4B/9B 版本通用能力明显下降（AIME 掉约 16–60 分），27B 才基本保住；评判依赖 GPT-5.6-Sol；单次 27B 训练约 5,000–8,000 GPU 小时，医疗管线总成本估约 24 万美元，其中 54.7% 花在环境构建上。对构建者：长任务 Agent 的瓶颈正在从算法转向「可验证的环境」，9,000+ 环境语料已开源。

来源：arXiv:2610.05923 · VERA

工具 Tools

工具Claude for Google Workspace 公测：Docs / Sheets / Slides 侧边栏直接改文件，另有 Google 文件连接器

Anthropic 10 月 6 日在所有付费方案上开放 Claude for Google Workspace 公测：侧边栏里的 Claude 能读到当前打开的文档、表格或幻灯片，以及你选中的文本、单元格或页，然后直接改原文件。在 Sheets 里可以写公式、做数据透视表和原生图表，复杂的连接或清洗会把数据区域拉进 Python 处理后再写回；在 Slides 里按现有版式生成新页，并检查元素重叠或越界。

默认是「Ask before edits」，每处修改都弹审批卡片，也能切到「Accept all edits」让它一路改完。侧边栏沿用账户里的模型、连接器和 skills；企业版的 Compliance API、CMEK、OpenTelemetry 审计导出同样适用；另一套 Docs/Sheets/Slides 连接器（beta）可以从 Claude 对话里新建和编辑 Google 文件，权限跟随 Google 共享设置。对构建者：Office 类 Agent 正走向「在原文件里逐条审批编辑」的交互方式，企业部署前要先想清楚默认审批模式和审计链路。

来源：Claude · Claude now works with Google Docs, Sheets, and Slides · The Verge

工具Musubi PolicyLM-1.7B：读你自己写的审核规则、一次前向就给每类打分的开源「决策模型」

Musubi 10 月 6 日以 Apache-2.0 开源 PolicyLM-1.7B，面向实时内容审核。它把「平台规则 + 消息」一起输入，一次前向就给每个自定义类别输出 0–1 分，不生成任何文本，所以改规则不用重新训练，也没有缓存要重建。官方数据：24GB L4 上、6 个类别时，单条短消息中位延迟 35ms；上下文 2,048 token（规则和消息合计）；评测覆盖 19 种语言，英语最强。

它基于 BidirLM-1.7B-Embedding（源自 Qwen3-1.7B-Base），训练数据包括 NVIDIA Nemotron Safety Guard v3、阿里 XGuard-Train-Open-200K、PolyGuardMix 和合成数据；自带的预处理会还原形近字、拆开的字母和 base64，在官方测试集上多抓到 10–12 个点的伪装违规。局限：只看文本、只看单条消息、不给理由。对构建者：这是 10-02 日报提到的「决策模型」路线在审核场景的落地，适合放在大模型前面做全量初筛，处罚类动作仍应交给人工或更大的模型复核。

来源：Musubi · Introducing PolicyLM-1.7B（2026-10-06） · Hugging Face · musubilabs/policylm-1.7b

安全 Security

安全Anthropic 把网络安全能力改成三级审核放行：Defense / Red Team / Specialized，并公开分级拦截实测

Anthropic 10 月 6 日把 Project Glasswing 和原 Cyber Verification Program 合并成新的三级 CVP，各级都能用 Claude Opus 5.5、Sonnet 5.5、Mythos 5.1 及后续模型。Defense 级面向事件响应、恶意软件逆向、漏洞验证，开源维护者和有漏洞报告记录的个人研究者也能申请；Red Team 级增加授权渗透测试，只接受机构申请；Specialized 级拦截最少，只给获准测试电网、航班系统、银行间转账等关键系统的机构，由 Anthropic 和美国政府一起审核。

官方用 CyScenarioBench 测了各级效果：不加入 CVP 时每个任务第一条提示就被拦；Defense 级 50 次试验中 46 次被拦；Red Team 级零拦截，Opus 5.5 完成 34/50，相当于无防护时 67.6% 的水平。参与计划要求保留数据用于滥用监控，今年秋天会推出兼顾零数据保留的 Enterprise Frontier Safeguards。对照同一天 Mistral 的「开放权重 + 不拒答」路线，对构建者：做安全产品的团队现在有两种路可选，一是闭源分级授权，二是自托管开放模型，合规和审计成本差别很大。

来源：Anthropic · Expanding the Cyber Verification Program（2026-10-06） · Reuters（经 StreetInsider）

产业与政策 Industry

产业Meta 与 Sierra 牵头 Personal Agent Protocol：基于 OAuth 的「个人 Agent 对接商家」开放标准

Sierra 10 月 6 日宣布，与 Meta 以及 Genesys、Instinct、Rocket、Shopify、Stripe、Walmart 一起制定 Personal Agent Protocol（PAP）。个人 Agent 先在商家网站上发现能力入口，以访客身份开始会话，需要账户权限时再登录，由用户决定只读还是可写；会话基于 OAuth，能跨渠道延续；之后可以走网页、走基于 MCP / OpenAPI 的 API，或者直接和商家自己的 Agent 对话。v0.1 规范和参考实现计划本月发布。

TechCrunch 同日的报道说明了为什么需要它：Amazon 已开始屏蔽 Meta 的 Muse Agent；Walmart 虽然是合作方，但「验证你是人类」的按钮会把 Agent 踢出去；Yelp、各航空公司等也在拦截或限制 Agent。对构建者：如果你做面向消费者的 Agent，「靠模拟点击硬闯」会越来越行不通；如果你是商家一方，值得关注 PAP 规范，用 OAuth 范围加审计来管理 Agent 流量，而不是一刀切屏蔽。

来源：Sierra · Introducing Personal Agent Protocol（2026-10-06） · TechCrunch

政策美参议员 Hawley 与 Murphy 提出 AI Agent Accountability Act：把《计算机欺诈与滥用法》延伸到 Agent 开发者和运营者

据 MeriTalk（10-06），这项两党法案规定：明知而运行的 AI Agent 若因鲁莽行为造成黑客式损害或损失，运营者适用 CFAA 条款；开发者如果知道或应当知道 Agent 有黑客能力却没有采取合理防护，要承担刑事和民事责任；美国司法部长和各州总检察长可以起诉，要求停止相关行为。

这目前还只是提案，能否通过尚不确定。但它与近期 Agent 越权事件（见 10-03、10-06 日报）直接相关。对构建者：「合理防护」很可能成为今后的举证焦点，包括出站流量白名单、权限隔离、速率限制和完整的操作日志，现在就值得作为工程默认项补上。
