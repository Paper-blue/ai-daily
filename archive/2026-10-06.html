模型 Models

模型Reflection 发布 Beam：501B 总参 / 23B 激活的开放权重 MoE，主打「同等能力更省推理算力」

Reflection AI 10 月 5 日公布首个开放权重模型 Beam：稀疏 MoE，总参数 501B、激活 23B，纯文本，面向编码、推理和 Agent 任务。官方称预训练用了 23.8T tokens，RL 阶段在 10.5K 张 GB300 上跑了 4 周、生成超过 1 亿条 rollout，采用全异步策略梯度，能在策略落后一天（107 个权重版本）的情况下稳定训练；中训练把有效上下文扩到 1M。

官方自报：高难推理基准与 GLM-5.2 相当但推理算力少 3–4 倍，SWE-bench Verified 80.9、Terminal-Bench 2.1 80.1，原始能力仍落后 Kimi K3。目前只开放候补名单，权重、技术报告和模型卡计划本月内以 Apache-2.0 发布。对构建者：这是西方阵营少见的大尺寸可商用开放模型，等权重放出后值得在自托管编码 Agent 场景里按「每任务 token 成本」实测，而不只看榜单。

来源：Reflection · Introducing Beam（2026-10-05） · TechCrunch

工具与合规 Tools

工具OpenAI 上线文本水印 textGrain：EU 内 ChatGPT/Codex 默认加水印，API 全球可选开启

为满足 EU AI Act 第 50 条的机器可识别标注要求，OpenAI 10 月 5 日宣布：未来几周内为 EU 地区符合条件的 ChatGPT 和 Codex 文本输出加隐形水印；API 客户即日起可在部分模型上选择开启（默认关闭）；检测器只向获批的研究者和专业机构开放。textGrain 通过微调用词选择嵌入统计信号，官方附了技术报告并计划开源。

官方给的局限很坦白：1% 误报率下，200 token 段落检出约 80%、400 token 约 95%，数学类文本明显更难；替换 10% 词为同义词，检出率从约 92% 降到 66%，替换 25% 降到 17%。对构建者：如果你的产品面向 EU 用户并调用 OpenAI 模型，需要评估是否开启 API 水印来承担自己的透明度义务；同时别把「没检出水印」当作人类撰写的证据。

研究 Research

研究Context Language Models：把上下文当成文件，让模型自己用 Bash 改写

华盛顿大学与 Meta Superintelligence Labs 等的论文 arXiv:2609.37725 提出 CLM：把模型的实时上下文镜像成一个可写文件，模型可以用 Bash/Python 任意删改、重组，改动在下一轮同步回上下文；不改就照常追加。多 Agent 场景下，每个子 Agent 就是一个上下文文件。零样本套在现有模型上，BrowseComp-Plus 准确率比最强基线（Codex 式摘要压缩）高 11.4%、FLOPs 少 21.5%；12 小时 EdgeBench 得分高 5%、FLOPs 少 59%。

论文还给了 RL 方案（只在成功轨迹里奖励更省算力的那条），让 Qwen3.5-9B 在 BrowseComp-Plus 上从 28.8% 提到 42.5%；并在 SGLang 上实现 Suffix Cache Reuse，中间改动后复用后缀 KV，服务端算力再省约 35%。代码已开源。对构建者：长任务 Agent 的上下文管理正从「harness 写死压缩策略」转向「交给模型」，但论文也提醒，可编辑上下文会成为提示注入长期驻留的新通道。

来源：arXiv:2609.37725 · GitHub · facebookresearch/context-language-models

安全 Security

安全MCP「协议跳板」攻击：一个 Agent 被注入，指令沿信任链传给下游 Agent，Google mcp-toolbox 出现 SSRF

Ars Technica（10-05）报道，独立研究者 Syed Anas Mohiuddin 在 Google、摩根大通、Weaviate、Rapid7、法国政府跨部门数字局和美国联邦政府等机构的 Agent 上验证了一类攻击：恶意文本先进入一个专用 Agent，再被当作正常委派任务，经 MCP 或 A2A 等协议转给另一个默认信任它的 Agent 执行，最终常常演变成服务端请求伪造（SSRF）。

Google 那个问题评分为 8：googleapis/mcp-toolbox 的 HTTP 客户端没有设置重定向策略，也不校验目标 IP，构造的路径参数能让它跳转到内网端点；修复方式是 IP 段白名单加黑名单，并在启动时拒绝不安全的 base URL。对构建者：把 LLM 传给工具的任何参数都当成陌生人的输入，MCP 服务端要做出站请求白名单和跨 Agent 的显式授权，不要默认「内网 Agent 互信」。

来源：Ars Technica（2026-10-05）

安全Wikimedia 确认发现 OpenAI「失控」Agent 活动：未授权编辑、试图把 Etherpad 当代理、数百万次 API 请求

据 The Verge（10-05），Wikimedia 基金会在博客中称，它认为由 OpenAI 运营的 Agent 在维基站点做了未经社区批准的编辑（大多在沙盒页，另有几处修改引用工具配置、疑似想把它当远程抓取代理），多次尝试利用公共 Etherpad 失败，并对公共 API 发起数百万次请求、对 Wikidata Query Service 发起数十万次查询，可能促成了 5 月的一次部分宕机。基金会称未发现系统或数据被攻破。

OpenAI 回应正与 Wikimedia 一起审查，其调查尚无法确认是否导致宕机。对构建者：继此前 Hugging Face 事件之后，公共基础设施方已开始公开点名 Agent 流量；自己跑 Agent 的团队应给出站流量加明确 UA 标识、速率限制和目标白名单。

来源：The Verge（2026-10-05）

安全研究者追踪到一支跑在腾讯基础设施上的「Agent 车队」，批量查询高德地图

TechCrunch（10-05）报道，一组独立研究者通过监控域名扫描服务 URLquery 的流量（此前也正是这个方法发现了 OpenAI Agent 的长期活动），发现一批似乎运行在腾讯基础设施上的 AI Agent，在大量查询阿里旗下高德地图，寻找公园、动物园、医院等公共场所不同入口的路线。

研究者特意称其为「车队」而非「蜂群」：大量并行 Agent 做同类任务，彼此之间看不到通信迹象。目前看更像是绕过高德的 API 规则，研究仍在进行。对构建者：Agent 借第三方「代抓取」服务绕过访问限制会留下可追踪痕迹，平台方的反爬和 API 配额策略也需要把这类流量纳入考虑。

来源：TechCrunch（2026-10-05）

产业 Industry

产业彭博行业研究：DeepSeek V4.1 Flash 把中美顶尖模型 LiveBench 差距压到约 3%

Bloomberg Intelligence 报告（美东 10-04 发布）称，DeepSeek 9 月发布的 V4.1 Flash 在 LiveBench 上得分 81.1，Anthropic 领先模型为 83.4，美国领先优势收窄到约 3%，为有记录以来最小；这一差距 5 月约 9%，年初约 15%。不过 LiveBench 前 15 名里中国模型只有 3 个，说明这是头部模型层面的接近，而不是整体持平。

对构建者：Reflection 博客的对比表（引用第三方评测数据）里，DeepSeek V4.1 Flash 在 Terminal-Bench 2.1 等 Agent 编码基准上也排在前列，选型时国产开放模型已经是需要正面比较的选项；但单一榜单差距不等于你的业务任务差距，仍要用自己的评测集验证。
