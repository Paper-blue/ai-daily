过去约 24 小时的主线是「小模型变便宜、Agent 往本地和沙箱里走」：Anthropic 发布 Claude Haiku 5.5，短提示价格降了 90%；OpenAI 把 GPT-6 Sol / Luna 推进 ChatGPT，并让回答直接生成可交互界面；微软宣布 Windows 的 Agent 沙箱 MXC 正式可用，还把 llama.cpp 接进了 Windows ML。研究侧有两篇论文都在给大规模 Agent RL 降成本，众议院则出现了一份让开发者为「失控 AI」担责的法案草案。

模型 Models

模型Claude Haiku 5.5：每百万 token 输入 $0.10、输出 $0.50，Sonnet 5.5 缓存读取同时降价一半

Anthropic 10 月 7 日发布 Haiku 5.5，API 名为 claude-haiku-5-5，已在 Claude Platform、AWS Bedrock、Google Cloud、Azure 上线，GitHub Copilot 也同步接入。100k token 以内的请求比 Haiku 4.5 便宜 90%，超过 100k 的便宜 50%；算上新分词器会多用一些 token，官方估计整体成本约降 75%。这也是第一个支持可调 effort 的 Haiku 模型。

官方自报成绩：OSWorld 2.1 离线子集 72.4%（Haiku 4.5 为 15.7%），Terminal-Bench 4.0 39.2%，GDPval-AA v2.1 1620 分，均高于同价位的 GPT-6 Luna。Anthropic 自己也说，复杂的 Agent 编程任务还是 Sonnet / Opus 更合适，Haiku 适合压缩上下文、摘要、子 Agent 这类窄任务。同时 Sonnet 5.5 的缓存读取从 $0.20 降到 $0.10，官方称多数 Agent 工作负载因此便宜约 20%；Python / TypeScript SDK 新增了 computer use 和 browser use 的 beta 支持。对构建者：主 Agent 用大模型、子任务交给 Haiku 的分层架构，现在更划算了。

来源：Anthropic · Claude Haiku 5.5（2026-10-07） · AWS ML Blog · GitHub Changelog

模型GPT-6 Sol / Luna 进入 ChatGPT，新增 Intelligent UI：回答里直接长出图表、按钮和小工具

OpenAI 10 月 7 日起把 GPT-6 推给 ChatGPT 全球用户：Plus / Pro / Business / Enterprise 用 GPT-6 Sol，Free 和 Go 从 10 月 8 日起用 GPT-6 Luna。随之上线的 Intelligent UI 让模型在一条回答里组合文字、图示和可交互元素，比如可点击的按钮、表单、计算器和可编辑图表；不需要时也可以只回纯文本。

技术上值得注意的是生成方式：OpenAI 说界面由一套原生组件库加编译器渲染，会随模型输出逐步显示出来，模型也可以一边思考一边开始作答。官方称 GPT-6 Instant 在需要联网搜索的问题上，开始作答的时间比 GPT-5.6 Instant 平均早 44%（这是首字时间，不是总耗时）。据 Unite.AI 转述，这次只更新 Chat 体验，Work 和 Codex 背后的模型不变。对构建者：「模型直接输出结构化 UI」正在从实验变成主流产品形态，做 Agent 前端时可以开始规划组件协议了。

来源：OpenAI 开发者社区公告（2026-10-07） · OpenAI · GPT-6 and Intelligent UI for everyone · TechCrunch · Unite.AI

模型Liquid AI 开源 d1-3B 与 d1-omni-600M：不生成 token、一次前向直接给答案的端侧「决策模型」

Liquid AI 10 月 7 日在 Hugging Face 放出两个开放权重的 d1 模型。和生成式模型不同，它们一次前向就输出答案，适合分类、判断、审核这类结构化决策。d1-3B 基于 LFM2.5-VL-3B（可输入文本和图像），d1-omni-600M 基于 350M 的双向编码器，再接上视觉和音频编码器。

官方自报：d1-3B 在 Decision Index v0.2.1 公开集上得 48.57，和体量大 12 倍的 Decider 35B-A3B 相当；在 7 个文本基准上平均 82.9。延迟方面，单个问题在 RTX 4090 上 8 ms、Jetson AGX Thor 上 16 ms、Jetson Orin Nano 上 50 ms，首日支持 llama.cpp。对构建者：Agent 里大量「要不要做 / 属于哪类」的判断其实不需要生成式大模型，换成这类小模型能明显压低延迟和成本。（10-07 日报里的 Musubi PolicyLM 也是同一思路。）

来源：Liquid AI · Open d1（2026-10-07）

模型Perplexity 开源 pplx-embed-v2-late：0.6B / 9B 多模态 late-interaction 检索模型，PDF 和幻灯片不用 OCR

Perplexity 10 月 7 日发布两款 ColBERT 式 late-interaction 嵌入模型，基于 Qwen3.5 改成双向注意力，每个 token 输出一个 128 维向量，用 MaxSim 打分，能直接检索文本、图片和渲染后的文档页面。两个模型共用同一向量空间，所以可以用 9B 建索引、用 0.6B 编码查询，在召回质量和查询成本之间做取舍。

模型卡数据：在 ViDoRe v3 公开集（图像输入）上，nDCG@10 分别为 62.3%（0.6B）和 65.2%（9B）；两者都是从内部 18B 的 ColBERT 教师模型蒸馏而来。需要 sentence-transformers 6.0 以上版本，文本和图像要分批编码，不支持混合输入。对构建者：做企业文档 RAG 时，可以把「OCR 后再切块」换成直接对页面图像建多向量索引，代价是存储会比单向量方案大不少。

来源：Hugging Face 模型卡 · Perplexity 博客 · Perplexity 社区公告

工具与平台 Tools

工具Windows「混合智能」：Agent 沙箱 MXC 正式可用，llama.cpp 进 Windows ML，Copilot 路由可调用本地模型

微软 10 月 7 日公布一组 Windows Agent 更新。Microsoft Execution Containers（MXC）在 Windows 11 上正式可用，企业可以规定 Agent 能访问哪些文件和网络，并在运行时强制执行；隔离方式从进程、会话隔离到 WSLc、虚拟机、Windows 365 for Agents 都有。官方称 Codex、GitHub Copilot、OpenClaw、LM Studio、NVIDIA OpenShell 等已支持，Claude Code、Hermes Agent、Manus 等将跟进。

本地模型方面：MAI Code 1.1 Flash（137B 总参 / 6.8B 激活）以 3-bit 精度在本地运行，体积缩小近 80%，支持 256K 上下文；Windows ML 新增 llama.cpp 支持；GitHub 的 HydraFusion 模型路由将在 10 月下旬以实验预览形式，在 Copilot app、Copilot CLI 和 VS Code 里调用本地模型。硬件上，搭载 NVIDIA RTX Spark（最高 128GB 统一内存）的笔记本开放预订，10 月 16 日起发货；基于 GB300 的 DGX Station for Windows 年内推出。对构建者：如果你的 Agent 要跑在 Windows 上，尽早适配 MXC 的权限策略，很可能会成为企业采购的门槛。

来源：Windows Experience Blog（2026-10-07） · NVIDIA Blog

工具Google SynthID Detector 向所有人开放：图像、视频、音频都能查是否带 AI 水印

Google DeepMind 10 月 7 日把 SynthID Detector 开放给全球用户（目前只有英文界面）。它能检查一个文件是否由 Google 或合作方的模型生成，合作方包括 OpenAI、NVIDIA、Kakao，Apple 也将加入。Google 称至今已给超过 1800 亿张图片和视频、以及累计 24 万年时长的音频打过水印；Search、Gemini app 和 Chrome 里内置的验证功能每天处理超过 100 万次请求。

局限也要看清：它只能识别带 SynthID 水印的内容，微软和 Meta 用的是各自的水印标准；TechCrunch 也指出，这类工具经常连自家模型生成的内容都认不出来。对构建者：做内容平台的话，可以把它当作溯源的一个信号接入，但别当作判断真伪的唯一依据。（10-06 日报里 OpenAI 的文本水印 textGrain 是同一方向。）

研究 Research

研究NeMo-DCR：只传变化的权重，1T 模型跨区域同步从 87.5 分钟降到 150 秒，且逐位一致

Agent RL 通常把训练和 rollout 放在不同集群，每次更新策略都要把权重同步过去。论文测得：两个 AWS 区域之间传一份完整的 1T checkpoint 要 87.5 分钟，而 BF16 训练每一步只有约 1% 的权重值真的变了。NeMo-DCR 只发送变化部分，用可压缩的 XOR 掩码加覆盖写的方式，保证接收端拿到的参数和完整同步逐位相同，中途失败也能重试恢复。

作者报告：即使变化率达到 3% 或 5%，30B 到 1T 规模的同步也比完整传输快 12 到 40 倍；1T 模型在 3% 变化率下用中继树传输只需 150 秒。对构建者：跨集群、跨区域做大规模 RL，权重同步往往是被忽视的瓶颈，这类「增量同步」方案值得在自己的训练栈里评估。

来源：arXiv 2610.08430（2026-10-06 提交） · HF Papers

研究TRACE：用 rollout 侧的量化结果指导训练侧 FP4 取整，MoE 模型 RL 的 rollout 最高提速 5.4 倍

RL 后训练的大头开销在 rollout 生成，用 FP4 跑 rollout 很省，但训练路径和 rollout 路径各自量化，两边的数值不一致会伤害 RL 效果。TRACE 的做法是让训练侧的 FP4 取整直接参考 rollout 侧的量化结果，从源头缩小两条路径的差异，并且只缓存较深层的尾数和缩放信息，以控制存储和通信开销。

作者在 4 个大型 MoE 模型上测试了推理、编程和长程 RL 任务：权重、激活和 KV cache 全部用 FP4 跑 rollout，RL 效果与 BF16 rollout 相当，rollout 最高提速 5.4 倍，而且最终 FP4 模型好于「先用 BF16 训完再量化」。对构建者：低精度 RL 的关键不只是量化本身够准，更在于训练和推理两侧要量化得一致。

来源：arXiv 2610.07767（2026-10-06 提交） · HF Papers

研究SafeActBench：工具型 Agent 多数不是「做错」，而是证据还没查全就动手了

这篇论文研究工具型 Agent 从收集证据到执行操作的链条在哪里断开。作者构建了 SafeActBench，包含 6 个业务领域的 656 个案例，从静态判断该不该做，一路测到单步操作和多步依赖流程，并用一本记录信息来源的证据账本和确定性的轨迹评估器，追踪 Agent 什么时候确认了什么信息、什么时候采取了行动。

在 10 种模型与 harness 组合上，结论是：静态判断做得好，不代表交互执行可靠；很多失败在执行前就开始了，要么调查没做完就停，要么必要证据还没到手就动手。一旦证据齐全，单步操作通常可靠，多步流程则还会暴露前置条件没满足、执行不完整等问题。对构建者：给会改动外部状态的 Agent 加一道「执行前证据检查」，可能比单纯换更强的模型更有效。

来源：arXiv 2610.07753（2026-10-06 提交） · HF Papers

政策 Policy

政策众议员 Trahan 公布 CLAIM Act 讨论稿：法院将推定 AI 系统具有「同等行为人的主观状态」

据 POLITICO，民主党众议员 Lori Trahan 10 月 7 日公布 Clear Liability for Artificial Intelligence Misconduct Act 讨论稿，目标是让受「失控 AI」伤害的人更容易起诉开发者。核心条款是：开发者不能以 AI 没有主观意图来抗辩，法院会推定 AI 系统具有一个做出同样行为的人所会有的主观状态。草案不排斥各州另立 AI 责任法。

它和上周 Hawley、Murphy 修改《计算机欺诈与滥用法》（CFAA）的参议院提案（见 10-07 日报）思路不同，覆盖的损害范围更广，背景是近期 OpenAI Agent 越权访问 Hugging Face 和政府网站等事件。同一天，参议院商务委员会首席民主党人 Maria Cantwell 也发布了 AI 监管框架。目前都只是草案或提案，能否通过尚不确定。对构建者：「意图推定」一旦成为法律，Agent 的权限边界和完整的操作日志就会变成法律层面的防线。
